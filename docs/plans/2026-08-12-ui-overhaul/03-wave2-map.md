## Диагноз: почему карту надо переделывать, а не подкручивать

### M-1. Три вложенных слоя, две конкурирующие камеры ✅ VERIFIED

```
dashboard_screen.dart:206   _WorldChartPanel   ← AnimationController + _zoom + _pan
dashboard_screen.dart:910   _AnimatedMap       ← LayoutBuilder + логика растяжения
world_map_widget.dart:38    WorldMapWidget     ← ЕЩЁ ОДНА камера: MapCamera + _camCtrl
```

`_WorldChartPanelState` (строки 610–760) держит `_zoomAnim`/`_panAnim`, считает кадр в
`_animateTo()` и передаёт `zoom`/`pan` вниз. Одновременно `_WorldMapWidgetState`
(строки 75–110) держит `_camera`/`_camFrom`/`_camCtrl` и в `didUpdateWidget` **запускает
собственную анимацию** к своей цели `_targetCamera()`.

Две системы камеры на одном виджете, каждая уверена, что управляет кадром. Это и есть
«зум на миллисекунду и прыжок назад» — комментарий об этом глюке лежит прямо в коде
(`dashboard_screen.dart:656`). То есть симптом знали, а причину не убрали, потому что
причина архитектурная.

### M-2. География — один SVG-path без идентификаторов ✅ VERIFIED

```
$ grep -c "<path" assets/maps/world.svg              → 1
$ grep -coE 'class="[a-z]{2}"' assets/maps/world.svg → 0
$ grep -oE 'viewBox="[^"]*"' assets/maps/world.svg   → viewBox="0 0 5760 2880"
```

Весь мир — **одна фигура**. Ни id, ни кодов стран. Следствия: нельзя подсветить страну
сервера, нельзя окрасить регион по загрузке, нельзя сделать hit-test по стране, нельзя
показать «вы здесь → сервер там» через выделение территорий. Доступны только булавки
поверх картинки. Любая содержательная переработка требует замены геометрии.

### M-3. Проекция ломается растяжением ✅ VERIFIED

```
world_map_widget.dart:167    fit: BoxFit.fill
```

Вся точность `projectX/projectY` (строки 68–69) построена на том, что SVG — честная
эквидистантная проекция 2:1. `BoxFit.fill` эту точность уничтожает. В `_AnimatedMap` есть
комментарий-признание: «minor aspect distortion is visually…». На телефоне искажение
перестаёт быть minor: 2:1 карту вжимают в почти квадратный бокс, Гренландия расплывается,
булавки уезжают от берега. На вашем скриншоте центральная панель — вертикальный мазок,
в котором география не читается вообще.

### M-4. 1.7 МБ мёртвых ассетов ✅ VERIFIED

```
$ du -ch assets/maps/*.svg | tail -1  → 1,7M
$ grep -rn "world_equirect" lib/       → НИ ОДНОГО вхождения
```
`world_equirect_test.svg` (1.37 МБ) и `world_equirect_test2.svg` не используются и не
объявлены в pubspec.

### M-5. Города — ручная таблица на 140 строк ✅ VERIFIED

`lib/core/utils/city_coords.dart` — 183 строки, ~140 записей вида
`'moscow': LatLon(55.75, 37.62)`, с ручными алиасами (`kiev`/`kyiv`,
`saint petersburg`/`st petersburg`/`petersburg`). Сервер, чьего города нет в таблице, не
получает булавку вообще. Масштабируется плохо: каждый новый регион — правка кода.

### M-6. Что в карте сделано правильно и должно остаться

- `MapCamera` (`shared/widgets/map_camera.dart`, 99 строк) с отдельным тестом
  `test/map_camera_test.dart` — математика кадрирования уже отделена от виджета. Это
  готовый фундамент, переиспользовать.
- `projectX/projectY` — точная линейная проекция, корректна при неискажённом рендере.
- Решение убрать ручной pan/zoom (докстринг, строки 34–37: «Manual pan and zoom were
  removed because they let the map be dragged out of view with no way back») — правильное
  продуктовое решение. **Не возвращать свободное перетаскивание.**
- Отказ от булавки-заглушки в Москве, когда GeoIP ещё не ответил
  (`dashboard_screen.dart:844`: «Omitted entirely until GeoIP resolves, rather than planting
  a placeholder somewhere the user is not») — честное поведение, сохранить.

## T2.1 — Заменить геометрию карты на адресуемую

**Приоритет:** P1. **Блокирует:** T2.2+. **Оценка:** 4 ч.

**Цель:** получить географию, где каждая страна — отдельная фигура с ISO-кодом.

**Шаги.**

1. Взять public-domain источник контуров стран (Natural Earth 1:110m — общественное
   достояние, подходит по лицензии). Нужен уровень детализации 110m: 50m даст лишние
   мегабайты без пользы на экране 400px.
2. Сгенерировать SVG в эквидистантной проекции с `viewBox="0 0 5760 2880"` — **сохранить
   существующий viewBox**, чтобы `projectX/projectY` продолжали работать без правок.
3. Каждая страна — отдельный `<path id="RU" class="country">` с ISO 3166-1 alpha-2.
4. Бюджет размера: **≤ 250 КБ**. Если больше — упростить геометрию (Douglas–Peucker),
   а не брать более грубый источник.
5. Удалить `world_equirect_test.svg` и `world_equirect_test2.svg` (1.7 МБ мёртвого груза).
6. Создать `lib/core/utils/country_paths.dart` — отображение ISO-кода в путь SVG для
   подсветки.

**Приёмка:**
```bash
grep -c "<path" flutter/assets/maps/world.svg        # ожидаемо ~170-250
grep -coE 'id="[A-Z]{2}"' flutter/assets/maps/world.svg  # ожидаемо ~170-250
du -h flutter/assets/maps/world.svg                  # ожидаемо ≤ 250K
ls flutter/assets/maps/                              # world_equirect_test* отсутствуют
```
Плюс скриншот отрендеренной карты — визуально проверить, что континенты на местах и
проекция не искажена.

**НЕ ДЕЛАТЬ:** не менять `viewBox`; не брать источники с несовместимой лицензией; не
добавлять карту растром (PNG) — потеряется масштабируемость и возможность подсветки.

## T2.2 — Одна камера вместо двух

**Приоритет:** P0 для карты (корень глюка). **Зависит от:** T2.1. **Оценка:** 5 ч.

**Цель:** ровно один владелец состояния камеры.

**Шаги.**

1. Удалить из `_WorldChartPanelState` (`dashboard_screen.dart:610-760`): `_zoom`, `_pan`,
   `_zoomAnim`, `_panAnim`, `_animateTo()`, `_ctrl`. Панель становится тонкой: получает
   данные, отдаёт в карту.
2. Удалить класс `_AnimatedMap` (`dashboard_screen.dart:910+`) целиком — его логика
   растяжения переезжает внутрь карты, где ей и место.
3. `WorldMapWidget` остаётся **единственным** владельцем камеры на базе существующего
   `MapCamera`. Публичный API:
```dart
WorldMapWidget({
  required List<MapPin> pins,
  MapPin? youPin,
  bool connected = false,
  void Function(MapPin)? onPinTap,
  /// Что кадрировать. Камера — производная от состояния приложения,
  /// а не от жестов пользователя.
  MapFraming framing = MapFraming.world,
})
```
4. `enum MapFraming { world, youAndActive, activeOnly }` — вместо передачи сырых
   `zoom`/`pan` снаружи.
5. Сохранить поведение: выбор сервера кадрирует «вы + сервер», сброс выбора возвращает
   мир, анимация 450 мс.

**Приёмка:**
- `grep -n "_zoomAnim\|_panAnim\|_AnimatedMap" lib/features/dashboard/dashboard_screen.dart`
  → **пусто**
- `grep -c "AnimationController" lib/shared/widgets/world_map_widget.dart` → **1**
- `flutter test test/map_camera_test.dart test/world_map_test.dart test/world_map_widget_test.dart`
  → зелёные
- **визуальная проверка обязательна:** выбрать сервер, снять скриншот через 100 мс и через
  600 мс. Прыжка кадра быть не должно. Это ровно тот дефект, который пробники не ловят —
  проверять глазами, A/B-скриншотами.

## T2.3 — Убрать искажение проекции

**Приоритет:** P1. **Зависит от:** T2.2. **Оценка:** 3 ч.

**Проблема:** `BoxFit.fill` (`world_map_widget.dart:167`) ломает проекцию, на которой
построена вся математика булавок.

**Решение — не «поставить BoxFit.contain»**, иначе на телефоне появятся большие пустые
поля сверху и снизу, что и пытались обойти растяжением. Правильно: **кропать, а не тянуть.**

```
Контейнер шире, чем 2:1  → показать полную ширину, обрезать по вертикали симметрично
Контейнер уже, чем 2:1   → показать полную высоту, обрезать по долготе,
                            центрируя на интересующей области (вы + активный сервер)
```

**Шаги.**

1. Заменить `BoxFit.fill` на `BoxFit.cover` + `Alignment`, вычисляемый из текущего кадра.
2. `projectX/projectY` дополнить обратным преобразованием «нормализованные координаты →
   координаты внутри видимой области», чтобы булавки были привязаны к географии, а не к
   размеру бокса.
3. Тест `test/map_projection_test.dart`: для 6 контрольных точек (Лондон, Москва, Токио,
   Сан-Паулу, Сидней, Найроби) при трёх соотношениях сторон бокса (2:1, 1:1, 3:4) булавка
   попадает в ожидаемую область с допуском ≤ 2% от ширины.
4. При очень узком боксе (телефон, портрет) — не пытаться показать весь мир: кадрировать
   регион вокруг «вы + сервер». Мир на 360dp всё равно нечитаем.

**Приёмка:** тест проекции зелёный; скриншоты при 360×640 и 1280×720 — континенты не
расплющены, булавки на берегу, а не в океане.

## T2.4 — Подсветка стран и содержательный визуал

**Приоритет:** P2. **Зависит от:** T2.1, T2.3. **Оценка:** 5 ч.

Теперь, когда страны адресуемы, карта может показывать то, что раньше было невозможно.
Всё — в палитре Atlas, без новых цветов.

1. **Страна активного сервера** — заливка `accentDim` (`0x26B85C38`), контур `accent`.
2. **Страны с доступными серверами** — контур `border`, заливка на 8% сильнее фона:
   пользователь видит географию покрытия, не читая список.
3. **Страна клиента** (по GeoIP) — тонкая штриховка `info` (`#4B6B7A`).
4. **Маршрут «вы → сервер»**: сплошная линия `accent` при подключении, пунктир
   `textMuted` при выбранном-но-не-подключённом. Уже реализовано — сохранить.
5. **Легенда** в стиле атласа: моношрифт, капслок, разрядка, внизу карты. Скрывать при
   высоте бокса < 200dp.
6. **Подпись рисунка** «Figure 1 · Distribution of egress stations worldwide» — сохранить,
   это часть визуального языка.

**Запрещено:** анимированные «пульсары» на булавках чаще 1 Гц (дёргает глаз и жрёт батарею
на мобиле); неоновое свечение; тени под булавками; новые цвета вне палитры.

**Приёмка:** скриншот с 3+ серверами в разных странах — видно подсветку страны активного,
контуры доступных, легенду. Проверить обе темы (светлая и тёмная).

## T2.5 — Мобильная компоновка карты

**Приоритет:** P1. **Зависит от:** T2.3. **Оценка:** 3 ч.

**Проблема** ✅ VERIFIED: `dashboard_screen.dart:228` — на телефоне карта получает
`AspectRatio(aspectRatio: 2.0)`, то есть при ширине 336dp (360 минус отступы) высота
становится 168dp. В этот бокс втиснуты: карта, счётчик станций, кнопки зума, подпись
рисунка. На вашем скриншоте это и превратилось в неразборчивый вертикальный мазок.

**Решение по form factor:**

| Форм-фактор | Компоновка карты |
|---|---|
| narrow (< 400) | карта **скрыта по умолчанию**, вместо неё строка «Карта · 3 станции ›»; раскрывается тапом в полноэкранный лист |
| phone (400–600) | карта 16:9, счётчик станций в шапке, подпись рисунка скрыта, зум-кнопки убраны |
| tablet (600–900) | карта 2:1 в две колонки |
| desktop (900+) | как сейчас, три колонки |

Обоснование для narrow: карта на 336×168 не несёт информации, но занимает четверть экрана
и оттесняет главное — кнопку подключения и список станций. Полноэкранный лист по тапу даёт
карту, которую реально видно.

**Приёмка:** скриншоты 320 / 360 / 390 / 768 / 1280 dp; на 320 и 360 карта не сплющена;
кнопка подключения видна без прокрутки.

## T2.6 — Разрешение локаций: убрать зависимость от ручной таблицы

**Приоритет:** P2. **Оценка:** 4 ч.

**Проблема** ✅ VERIFIED: `city_coords.dart` — 183 строки ручной таблицы (~140 городов).
Сервер с городом вне таблицы не получает булавку.

**Шаги.**

1. Цепочка разрешения, в порядке убывания точности:
   `явные lat/lon из манифеста` → `таблица городов` → `центроид страны по ISO-коду`
   → `не показывать булавку` (не выдумывать координаты).
2. Добавить `lib/core/utils/country_centroids.dart` — центроиды по ISO-коду (~250 записей,
   генерируется из того же Natural Earth). Это гарантирует булавку для любой страны.
3. В Go-демоне: `internal/geoip/geoip.go` уже есть — проверить, отдаёт ли он страну сервера
   в `/v1/servers`, и если да, использовать вместо парсинга названия города.
4. Тест: сервер с неизвестным городом, но известной страной → булавка в центре страны;
   сервер без страны → булавки нет, приложение не падает.

**Приёмка:** тест на три случая (город известен / только страна / ничего не известно).
