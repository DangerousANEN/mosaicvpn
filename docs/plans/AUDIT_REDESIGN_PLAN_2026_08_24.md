## Часть 0. Диагностированные корневые причины (сессия 2026-08-24)

### 0.1 TUN/Proxy не работает на ПК пользователя
- **Причина**: пользователь запускает **портативную сборку v0.3.37** из `F:\ANEN\Downloads\MosaicVPN-Portable-x64-v0.3.37\`.
- v0.3.37 **не содержит** фиксов `8b8694c` (allowInsecure + sniff) и `675a995` (дедлок hot-reload):
  без `sniff` не работает DNS hijack; без `insecure:true` узлы с чужим SNI дают `bad certificate`.
- **Решение**: обновиться до v0.3.39 (уже на сайте). Проверено в Docker-контейнере: TUN и Proxy
  ходят с egress WARP, hot-reload настроек 0.1–0.2 c.
- Дополнительно: в v0.3.39+ Windows-раннер сам регистрирует `mosaicvpn://` (см. 0.2).

### 0.2 Кнопка «Добавить в MosaicVPN» на ПК ничего не делает
- Цепочка: кабинет → `POST /api/app-auth/issue` → страница `/enroll/callback?code&state`
  → кнопка с `href="mosaicvpn://enroll/callback?..."`.
- **Причина**: схема `mosaicvpn://` НЕ зарегистрирована в реестре (ни HKCU, ни HKLM):
  портативная сборка не запускает Inno Setup `[Registry]`, а self-registration в раннере отсутствовал.
- **Исправлено** (`4968a08`): `flutter/windows/runner/main.cpp` теперь при каждом старте идемпотентно
  создаёт `HKCU\Software\Classes\mosaicvpn{,\DefaultIcon,\shell\open\command}` с реальным путём exe.
  Логика проверена компиляцией и прогоном тестового TU (reg-значение = `"C:\...\MosaicVPN.exe" "%1"`).
- Останется проверить после сборки следующего релиза: клик по кнопке открывает приложение,
  URI долетает до `_completeDesktopWebsiteEnrollment` (app_links), подписка появляется без рестарта GUI.
- Релиз с фиксами ПК и Android: **v0.3.40** (self-registration + enrollment guard fix).
  Дополнительно на сайте: авто-запуск `mosaicvpn://` через 1.2 с на странице callback (один клик
  вместо двух), favicon-компас на всех страницах, защита от двойного сабмита кода.

### 0.3 Телефон: приложение открывается, но подписка не добавляется
- **✅ НАЙДЕНА И ДОКАЗАНА (2026-08-24, логи сервера + код)**: в `_completeWebsiteEnrollment`
  стоял guard `ref.read(daemonApiProvider) is! AndroidHostedDaemonApi`. Но `daemonApiProvider`
  ВСЕГДА возвращает обёртку `_ResolvedDaemonApi` (ленивый делегат) — проверка не проходила
  НИКОГДА, ни cold-, ни warm-start. Колбэк не потреблялся, `/api/app-auth/exchange` не вызывался.
  Логи: Aug 23 12:25–12:34 `issue`=200 ×11, `exchange`=0. Фикс: коммит 0003347 — прямой вызов
  `AndroidHostedDaemonApi.instance`. Релиз с фиксом: v0.3.40 (сборка CI 32693127808).
- Механика App Link корректна: manifest `autoVerify=true` + `assetlinks.json` на проде (отдаётся, отпечаток совпадает).
- Нативная передача: MainActivity кладёт URI в `pendingEnrollmentCallback` + шлёт
  `enrollmentCallbackReceived` в Dart; cold-start добивается через `consumeEnrollmentCallback` в postFrameCallback.
- Обмен кода: `POST /api/app-auth/exchange {code,state}` — эндпоинт существует (400/404/401 семантика живая).
- **Гипотезы для проверки** (в порядке вероятности):
  1. На телефоне стоит APK старее v0.3.38 (без этого флоу или с багом обмена).
     → Проверить версию на телефоне; поставить v0.3.39 APK.
  2. `_dio.post('/api/app-auth/exchange')` падает (таймаут 12s/20s на мобильной сети, сертификат)
     → ошибка показывается SnackBar'ом, который легко пропустить.
     → Добавить явный экран ошибки зачисления с кнопкой «Повторить».
  3. Race: `bridgeChannel.invokeMethod('enrollmentCallbackReceived')` уходит до того, как Dart
     зарегистрировал handler (warm-start из recent apps) — тогда стрим пуст, но pending остаётся;
     consume срабатывает только в postFrameCallback при initState (не на resume!).
     → ФИКС: дёргать `_completeWebsiteEnrollment()` в `AppLifecycleState.resumed` (didChangeAppLifecycleState уже наблюдается).
  4. Пользователь выходит из браузера до завершения exchange (страница закрывается) — обмен всё равно
     должен идти в приложении; если приложение открылось по https-ссылке, браузер не участвует.
- **Сделать**: логирование этапов зачисления (native+dart) в debug-лог; авто-retry exchange 2 раза.

### 0.5 «Флеш» экрана входа в кабинете (и в клиенте)
- Сайт: gate показывается по умолчанию, кабинет рендерился только после ответа API.
  **Исправлено**: профиль кэшируется в `localStorage.mv_profile_cache_v1`; на старте мгновенный
  `showAccount(cached)` + тихий `loadProfile()` рефреш; кэш чистится при logout/401.
- Клиент Flutter: аналогичная проблема — стартовый экран решается асинхронно без кэша.
  → ФИКС (клиент): рендерить последнее состояние из secure storage синхронно при старте
    (directToken/sessionToken уже там), сверку с демоном делать в фоне.

### 0.6 Auth-коды («странная тема»)
- Бот: алфавит без 0/O/1/I/L, 8 символов, TTL 10 мин, single-use, max 5 попыток,
  повторный выпуск инвалидирует предыдущий. Технически ок.
- UX-проблемы: пользователь должен успеть за 10 мин; непонятно откуда брать код; нет истории входов.
- → Улучшения: (а) в кабинете кнопка «Открыть бот» рядом с полем кода (глубокая ссылка t.me);
  (б) парольный вход уже есть — сделать его основным для вернувшихся, код — только первичная линковка;
  (в) показывать «последний вход: дата/устройство»; (г) увеличить TTL до 15 мин и показать таймер.

### 1.2 UX для «бабушек» (заимствования у открытых VPN-клиентов)
- **One-tap connect**: гигантская кнопка «Подключить», всё остальное спрятано (как у WireGuard app / Proton).
- **Onboarding-визард**: скачать с сайта → авто-открытие приложения → «Добавить» одним нажатием → подключено.
  Промежуточные страницы enroll должны сами открывать приложение (auto-click mosaicvpn:// через 1с).
- **Статус человеческим языком**: «Всё под защитой» / «Соединяемся…» вместо state=connected.
- **Автовыбор лучшего сервера** дефолтом (smart group min-latency уже есть — сделать его дефолтным выбором).
- **Понятные ошибки**: «Интернет не работает», «Подписка истекла — продлить?» с кнопкой на оплату.
- Референсы: ProtonVPN (простота + expert-режим), WireGuard (минимализм), Throne/Nekoray (экспорт конфигов).

### 1.3 UX для профессионалов
- Expert-режим (переключатель в настройках): raw JSON конфига sing-box, логи, ручные маршруты.
- Экспорт/импорт профилей, CLI (`mosaic`), MCP уже есть — подсветить в docs.
- Раздельное туннелирование per-app (Android already?) и per-domain правила — расширить routing UI.
- Тест серверов: показать таблицу пингов/потерь, авто-переключение при деградации (pool engine уже умеет).
