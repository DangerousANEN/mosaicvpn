# Переработка интерфейса: мобильный дашборд и карта

**Статус:** на реализацию
**Связано:** `PRD_v0.3.0.md`, `PLAN_v0.3.0.md`

---

## 1. Что не так сейчас

### 1.1 Мобильный дашборд (подтверждено скриншотом пользователя)

`dashboard_screen.dart:140` — три панели лежат в жёстком `Row` с `Expanded(flex: 3/4/3)`
и **ни одного брейкпоинта**. На экране 390 px каждая колонка получает ≈120 px за вычетом
отступов. Результат на телефоне:

- «DISCONNECTED» ломается по два символа в строку: `D I / S C / O N / N E / C T / E D`
- «No Sources Configured» рвётся на `N / o / So / ur / ce / s`
- название локации обрезается до `Dae...`
- карта сжимается в вертикальную полосу, хотя проекция требует 2:1

Причина одна: макет рассчитан на десктоп и применяется к телефону без изменений.

### 1.2 Карта (все платформы)

- `InteractiveViewer` + кнопки `+` / `−` / «сброс» — ручной зум и перетаскивание.
  Пользователь может увести карту за пределы виджета и «потерять» её.
- Размер задаётся долей свободного места, из-за чего на узких экранах карта
  вырождается в полоску.
- Выбор сервера никак не показан на карте: нет связи «вы → сервер».

## 2. Целевое поведение карты

### 2.1 Общие правила (десктоп и телефон)

1. **Ручное управление убрано.** Нет `InteractiveViewer`, нет кнопок зума,
   нет перетаскивания. Камера управляется только логикой приложения.
2. **Фиксированное соотношение 2:1** сохраняется всегда (equirectangular).
3. **Камера анимируется** между состояниями за 450 мс, кривая `Curves.easeInOutCubic`.

### 2.2 Три состояния

| Состояние | Камера | Пин сервера | Линия |
|---|---|---|---|
| **Idle** — ничего не выбрано | весь мир | обычный | нет |
| **Candidate** — сервер выбран | приближение так, чтобы клиент и сервер были видны | тусклый оранжевый | пунктирная |
| **Connected** — подключено | то же приближение | яркий оранжевый | сплошная |

Цвета берутся из темы, не хардкодятся:

- тусклый оранжевый: `c.accent.withOpacity(0.45)`
- яркий оранжевый: `c.accent`

### 2.3 Расчёт камеры для состояния Candidate / Connected

Даны нормированные координаты клиента `(ux, uy)` и сервера `(sx, sy)` в диапазоне 0..1.

```
minX = min(ux, sx);  maxX = max(ux, sx)
minY = min(uy, sy);  maxY = max(uy, sy)

padding = 0.15                       // 15% воздуха вокруг пары
spanX = (maxX - minX) + padding * 2
spanY = (maxY - minY) + padding * 2

scale = min(1 / spanX, 1 / spanY)
scale = scale.clamp(1.0, 4.0)        // не отдалять дальше мира, не ближе 4x

focusX = (minX + maxX) / 2           // центр между клиентом и сервером
focusY = (minY + maxY) / 2
```

Матрица: сдвиг так, чтобы `focus` оказался в центре виджета, затем масштаб `scale`.
Ограничение `clamp(1.0, 4.0)` не даёт «улететь» при совпадающих координатах
(клиент и сервер в одном городе) — иначе `spanX → 0` и `scale → ∞`.

### 2.4 Взаимодействие

**Десктоп:**

| Действие | Результат |
|---|---|
| Первый клик по серверу (в списке или на карте) | Candidate: тусклый оранжевый, пунктир, приближение |
| Повторный клик по тому же серверу | Connected: яркий, сплошная линия, подключение |
| Клик по другому серверу | Candidate переносится на новый сервер |
| Контекстное меню → «Подключиться» | Сразу Connected, **без двойного клика** |
| Большая кнопка «Engage Tunnel» | Подключается к текущему кандидату; если кандидата нет — к лучшему по стратегии |
| `Esc` | Сбрасывает кандидата в Idle |

**Телефон:**

Двойное нажатие на маленьком экране неудобно и провоцирует ошибочные подключения,
поэтому:

| Действие | Результат |
|---|---|
| Тап по серверу | Candidate + карта приближается, снизу поднимается панель с кнопкой «Подключиться» |
| Кнопка «Подключиться» в панели | Connected |
| Долгое нажатие | Контекстное меню (подключиться, в избранное, детали) |

Это соответствует разрешению «для телефона можешь менять».

## 3. Мобильный дашборд

### 3.1 Брейкпоинт

```
compact  : width <  600   → одна колонка, вертикальный стек
medium   : 600..900       → две колонки (статус+станции, карта во всю ширину)
expanded : width >= 900   → текущие три колонки (не трогаем, десктоп работает)
```

### 3.2 Порядок панелей на телефоне (сверху вниз)

1. **Статус подключения** — крупно, во всю ширину, кнопка «Engage Tunnel» тянется по ширине
2. **Карта** — во всю ширину с соотношением 2:1
3. **Станции** — список, минимум 20 символов имени видно

### 3.3 Требования к тексту

- «DISCONNECTED» — `FittedBox` + `maxLines: 1`, никакого посимвольного переноса
- Имя станции — `Expanded` + `TextOverflow.ellipsis`, бейдж пинга фиксированной ширины 64 px
- Минимальная ширина панели 280 px; если места нет — панель занимает всю ширину

## 4. Как тестируем (без сборки APK)

Пользователь просил не пересобирать APK на каждую правку. Проверяем через Flutter Web
в песочнице `devin-sandbox` под несколько размеров экрана:

| Профиль | Ширина × высота | Что проверяем |
|---|---|---|
| phone-small | 360 × 640 | нет посимвольного переноса, нет overflow |
| phone | 390 × 844 | основной кейс пользователя |
| tablet | 768 × 1024 | две колонки |
| desktop | 1440 × 900 | три колонки не сломаны |

Автопроверка (`scripts/ui_matrix_check.py`) через CDP:

1. поднять `flutter build web` и раздать статикой
2. для каждого профиля выставить viewport
3. поймать в консоли `RenderFlex overflowed` — это ошибка Flutter о переполнении
4. измерить `scrollWidth > innerWidth` — горизонтальная прокрутка
5. проверить, что подписи не разорваны (ширина текстового узла > 40 px)

Приёмка: 0 overflow-сообщений и 0 горизонтальных прокруток на всех четырёх профилях.
