## 1. Проблема

Релиз v0.2.0 собрался и опубликовался под три платформы, но продукт не пригоден к
использованию. Обратная связь владельца после установки Android-сборки:

> «На андроиде приложение выглядит отвратительно и неюзабельно вообще»

Ниже — разбор каждой claim из фидбэка с найденной причиной в коде. Причины
установлены чтением исходников, а не предположением.

| # | Симптом (со слов владельца) | Установленная причина | Файл |
|---|---|---|---|
| 1 | Не везде применяется тёмная тема | Хардкод цветов вместо токенов темы | `flutter/lib/features/**` |
| 2 | Группы не работают | Нет `GET /v1/groups`; группы приходят только внутри `/v1/manifest`, который у провайдера пустой | `internal/api/server.go` |
| 3 | Консоль открывается при подключении | `exec.CommandContext` без `SysProcAttr{HideWindow:true}` и `CREATE_NO_WINDOW` | `internal/state/singbox_backend.go:162` |
| 4 | Подписки иногда пропадают | Windows-путь сохранения: `os.Remove` + `os.Rename` без отката при сбое между ними | `internal/store/store.go:241-268` |
| 5 | Профиль не совпадает с действительностью | `ProviderProfile` рендерится из манифеста, локальное состояние игнорируется | `flutter/lib/features/provider_profile/` |
| 6 | Две вкладки под группы | `Subscriptions` (`MixedSubscriptionsScreen`) и `Groups` (`ManifestGroupsScreen`) дублируют сущность | `flutter/lib/app/app_shell.dart:55-63` |
| 7 | Слишком широкие группы на вкладках | Карточки без `maxWidth`, растягиваются на всю ширину | `subscriptions_screen.dart`, `manifest_groups_screen.dart` |
| 8 | Карта растянута, сервера и юзер неверно | SVG растянут на `availW×availH` без сохранения соотношения 2:1, проекция считает от искажённого холста | `flutter/lib/shared/widgets/world_map_widget.dart:86-99` |
| 9 | В дашборде помещается 5 символов имени | 15 вкладок + плотная сетка на 1977 строк в одном файле | `dashboard_screen.dart`, `app_shell.dart` |

Дополнительно требуется:
- Кастомная (пользовательская) подписка.
- Принципиальная переработка логики и дизайна групп.
- Пул бесплатных серверов с распределением по загрузке.
- Личный кабинет, связанный с Telegram-ботом и профилем в приложении.
- Заглушка платёжной системы lava.ru в трёх местах.
- Приведение сайта к требованиям платёжного провайдера.

## 2. Цели и не-цели

### Цели

- **G1.** Android-клиент пригоден к ежедневному использованию: единая тёмная тема,
  ≤ 6 вкладок, читаемые имена серверов, корректная карта.
- **G2.** Группы работают как основной способ подключения: одна вкладка, рабочий
  список с бэкенда, понятная логика выбора.
- **G3.** Трафик уходит напрямую клиент → сервер из пула. Наш сервер перестаёт быть
  транзитом и работает только как координатор и аварийный резерв.
- **G4.** Подписки не теряются; пользователь может добавить свою.
- **G5.** Личный кабинет с единой личностью в трёх точках: бот, приложение, сайт.
- **G6.** Сайт проходит модерацию платёжного провайдера.

### Не-цели (осознанно вне объёма v0.3.0)

- Реальный приём платежей: lava.ru встраивается **как заглушка** с полным контрактом,
  но без боевых ключей и списаний.
- iOS и macOS сборки.
- Перевод бота на новый бэкенд.
- Собственные VPN-серверы (используем пул + один аварийный узел).

## 3. Пользователи

| Роль | Сценарий | Ключевая метрика |
|---|---|---|
| Бесплатный пользователь | Ставит APK, жмёт «Подключиться», получает узел из общего пула | время до первого подключения < 30 сек |
| Платный пользователь | Оплачивает через бота, получает приоритетную группу | доступность приоритетных узлов ≥ 99% |
| Владелец сервиса | Смотрит нагрузку, управляет пулом | нагрузка на наш сервер < 5% от трафика |

## 4. Функциональные требования

### 4.1 Клиент (Flutter)

**FR-1. Навигация.** Свести 15 вкладок к 5: `Главная`, `Группы`, `Подписки`,
`Кабинет`, `Ещё`. Остальные экраны уезжают в `Ещё` как список.

**FR-2. Тёмная тема.** Все цвета — только через `ThemeColors.of(context)`.
Хардкод `Colors.white` / `Colors.black` / `Color(0xff…)` в `features/` запрещён,
проверяется тестом.

**FR-3. Карта.** Соотношение сторон 2:1 фиксировано (`AspectRatio(aspectRatio: 2.0)`),
проекция считается от реального размера SVG, пины совпадают с координатами.
Позиция пользователя берётся из GeoIP текущего выхода, а не из первого сервера.

**FR-4. Дашборд.** Имя сервера отображается полностью (минимум 20 символов) либо
переносится. Панель подписок не сжимает имя после замера пинга.

**FR-5. Кастомная подписка.** Пользователь добавляет свой URL или вставляет
конфиг из буфера; она равноправна с провайдерскими и не перетирается обновлением
манифеста.

**FR-6. Одна вкладка групп.** `MixedSubscriptionsScreen` и `ManifestGroupsScreen`
сливаются в один экран `GroupsScreen`. Карточка группы ограничена по ширине
(`maxWidth: 520`) и на планшете идёт в 2 колонки.

### 4.2 Демон (Go)

**FR-7. Без консоли.** Процесс sing-box стартует скрыто на Windows
(`SysProcAttr{HideWindow: true, CreationFlags: CREATE_NO_WINDOW}`).

**FR-8. Надёжное сохранение.** Запись состояния переживает сбой на любом шаге:
tmp → fsync → атомарная замена, при неудаче — восстановление из `.bak`.

**FR-9. Список групп.** Новый `GET /v1/groups` возвращает объединённый список:
группы из манифеста + локальные + встроенные пуловые.

**FR-10. Пул серверов.** Демон умеет забирать узлы из публичных источников только
по HTTPS, проверять их и держать актуальный список.

### 4.3 Система групп

Полная спецификация вынесена в отдельный документ:
`docs/GROUP_SYSTEM_SPEC.md`.

Кратко: 4 стратегии выбора (`urltest`, `weighted_round_robin`, `fallback`,
`direct_node`), 3 источника узлов (пул, подписка пользователя, аварийный узел),
распределение по загрузке, выбор по критерию (локация / минимальный пинг / скорость).

### 4.4 Личный кабинет и платежи

**FR-11. Единая личность.** Один `account_id` связывает Telegram-бота, приложение и
сайт. Привязка в приложении — по коду из бота.

**FR-12. Заглушка lava.ru.** Реализуется полный контракт (создание платежа, статус,
вебхук) с драйвером `mock`, переключаемым на боевой одним флагом конфига. Точки
подключения: бот, приложение, сайт.

### 4.5 Сайт

**FR-13.** Страницы под требования платёжного провайдера: контакты, оферта,
политика ПДн, возвраты, лицензия, карточки услуг с ценой. Все ссылки кликабельны и
ведут на рабочие страницы.

## 5. Нефункциональные требования

- **NFR-1.** Android: холодный старт < 3 сек на устройстве среднего уровня.
- **NFR-2.** Наш сервер не проксирует пользовательский трафик, кроме аварийного узла.
- **NFR-3.** Пул принимает источники только по HTTPS. HTTP-источник отклоняется.
- **NFR-4.** `go test ./...` и `dart analyze` — без ошибок.
- **NFR-5.** Отсутствие горизонтального переполнения на 360 / 390 / 768 px.

## 6. Критерии приёмки

Задача считается выполненной только при выполненном пункте «проверено», где
проверка — это реальный запуск, а не чтение кода.

| ID | Критерий | Как проверяется |
|---|---|---|
| AC-1 | Тёмная тема везде | скриншоты всех вкладок на Android в тёмной теме |
| AC-2 | Консоль не появляется | запуск на Windows, окна нет |
| AC-3 | Подписки не теряются | 50 циклов добавления/перезапуска, счёт совпадает |
| AC-4 | Карта корректна | пин Москвы попадает в Москву на 3 разрешениях |
| AC-5 | Группы работают | `GET /v1/groups` возвращает ≥ 1 группу, подключение проходит |
| AC-6 | Одна вкладка групп | в `app_shell.dart` ровно одна ссылка на экран групп |
| AC-7 | Имя сервера читается | 20+ символов видны после замера пинга |
| AC-8 | Пул раздаёт узлы | 10 клиентов распределены не менее чем по 3 узлам |
| AC-9 | Кабинет связан | код из бота привязывает аккаунт в приложении |
| AC-10 | Сайт соответствует | все 7 обязательных разделов на месте, ссылки живые |

## 7. Риски

| Риск | Влияние | Митигация |
|---|---|---|
| Публичные пулы отдают мёртвые узлы | Пользователь не подключается | health-check до выдачи, аварийный узел как резерв |
| Узлы из пула логируют трафик | Приватность | предупреждение в UI, приоритет проверенным источникам |
| lava.ru отклонит сайт | Нет приёма платежей | все 7 разделов делаются до подачи заявки |
| Слияние вкладок сломает состояние | Регресс | сначала тесты на роутинг, потом слияние |
