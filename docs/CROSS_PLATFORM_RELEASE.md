# MosaicVPN — кроссплатформенный релизный контур

Клиент использует один Flutter UI и один локальный Go daemon API. Это позволяет сохранить одинаковые сценарии входа, групп, баланса и доступа на всех графических платформах. Однако создание настоящего VPN-туннеля требует нативного backend-а и подписи приложения на каждой ОС; Flutter сам по себе не заменяет системный VPN API.

| Платформа | Состояние исходников | Проверка в текущем окружении | Обязательное условие для релиза |
| --- | --- | --- | --- |
| Linux | Flutter platform, Go daemon, tray и release bundle | `flutter analyze`, widget-тесты и `flutter build linux --release` | Пакетирование `mosaicd` и `sing-box` рядом с bundle; тест на чистом Linux VM. |
| Windows | Существующие Windows Flutter/installer файлы и Go daemon | Go-тесты общих модулей | Собрать на Windows runner, подписать installer и проверить TUN/kill switch с правами администратора. |
| Android | Существующий Android Flutter scaffold | Анализ и widget-тесты общих Dart-сценариев | Реализовать Android `VpnService`, безопасное хранение ключей и проверить на физическом устройстве. |
| iOS | Добавлен Flutter iOS scaffold | Анализ и widget-тесты общих Dart-сценариев | Реализовать Packet Tunnel Network Extension, настроить Apple entitlements и собрать/проверить в Xcode на macOS. |
| macOS | Добавлен Flutter macOS scaffold | Анализ и widget-тесты общих Dart-сценариев | Подписать bundle, приложить daemon и выполнить нативную VPN-интеграцию/проверку на macOS. |
| Web | Flutter web scaffold сохраняется как демонстрационный интерфейс | Анализ общих Dart-сценариев | Не позиционировать как VPN-клиент: браузер не может создавать системный туннель. |

## Единый UX-контракт

Все платформы используют общие Flutter-сценарии: Telegram pairing-code, email-вход, smart-группы, баланс, pause/resume, provider-neutral checkout, безопасный перевыпуск подписочной ссылки и раздел «Ещё» для продвинутых настроек. Токены хранятся и применяются локальным daemon-ом; Flutter-виджеты получают только безопасные данные, нужные для интерфейса.

## Перед выпуском каждой платформы

1. Собрать Flutter bundle на нативной ОС платформы.
2. Собрать `mosaicd` с целевой архитектурой и проверить запуск из app bundle.
3. Убедиться, что в release package есть `sing-box` и применимые нативные разрешения.
4. Выполнить smoke-test: вход, подключение к smart-группе, отключение, pause/resume, invoice и перевыпуск ссылки.
5. Проверить kill switch, DNS, IPv6, reconnect и обновление приложения на чистой машине/устройстве.

> До прохождения нативной проверки Android, iOS и macOS не должны рекламироваться как полностью готовые системные VPN-клиенты. Общий Flutter UI и account-функции уже имеют единый контракт, но системный tunnel backend должен быть заверен на каждой платформе отдельно.
